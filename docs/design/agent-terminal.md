# Agent terminal：设计基线

状态：行为设计与通信、PTY、存储选型已确认，并已通过 Gate A/B/C 运行验证（[技术验证结果](../research/terminal-technical-validation.md)）；输出解析选型已确认但尚未运行验证。生产实现按 [生产实现切片计划](terminal-production-implementation-plan.md) 逐片推进，尚未批准开始编码。

## 定位与范围

qingluan 是自用的 agent 基础设施，未来逐步承载更多工具与内容。Terminal 是本轮新增的能力模块，不是整个项目的定位；现有项目已包含 workspace/Pi session 管理、daemon、CLI、桌面端及其他能力的接口或占位。

首版范围：终端核心、本地常驻服务、TS client、pi adapter、只读观察 CLI。

非目标：Web UI、通用插件框架、独立权限系统、远端调度、SSH 密码/MFA、凭证管理、远端任务保活、任意全屏 TUI 的可靠观察或操作。

平台：Linux。

本文件记录已确认的行为与已验证的技术选型；生产 `.proto` 字段编号仍未冻结。RPC 全表、消息结构和状态转换见 [Terminal 协议 v1 草案](terminal-protocol-v1.md)；草案中的字段表示与未决项不等于已冻结的线协议。

## 职责

| 层 | 职责 |
| --- | --- |
| qingluan Rust 核心 | PTY、进程生命周期、日志、有限查询、退出事件持久化 |
| qingluan server / 观察 CLI | 多 session 管理、本地通信、只读观察 |
| TS client | 请求与响应、类型、连接恢复、显式游标、事件订阅；不依赖 pi |
| pi adapter | 宿主 session 映射、工具暴露、宿主审批、显示与通知 |

TS client 是自行实现的薄通信封装，不是自造网络栈。它不负责审批、宿主 UI 或通知策略；放在本仓库 `packages/qingluan-client`，是否独立发布尚未决定。

权限策略保持可独立演进，但首版不创建通用权限框架。

### 入口与现有架构

- CLI 面向人类的操作、管理与观察，保留已有机器可读模式；不再要求 Agent 的全部调用经过 CLI，也不要求每项能力都有 CLI 命令。
- Harness adapter 可通过 TS client 直接调用 daemon。现有 `packages/qingluan-pi` 的 `/ws` 仍可调用 CLI，不因本次约定调整而强制迁移。
- 当前仓库已经采用 `crates/qingluan-{core,protocol,config,cli,daemon,sandbox,storage}` 和 `apps/desktop` 分层；此前基于旧脚手架的 `backend/shared` 目录建议已撤回。
- 当前 daemon 提供 HTTP 端点，CLI health 和 Tauri 代码已有 HTTP 调用。首版 terminal 使用 gRPC over Unix socket，暂时保留既有 HTTP 调用，不把 CLI/Tauri 的整体迁移捆绑进 terminal 首版。
- 下文 Unix socket / 不开放网络端口限定新增 terminal 执行入口，不表示现有 daemon 已无 TCP 监听；临时保留 HTTP 不代表决定永久维持双协议。
- 本次仅更新入口约定及设计文档，不代表已实现 gRPC 或批准整体通信迁移。

### 已确认的模块归属（目标结构，尚未实现）

- 新增 `qingluan-terminal` crate：PTY、输出规范化、session 控制租约、配额、终端状态机、输入调度与订阅。
- 复用 `qingluan-storage`：SQLx、迁移、分段日志、索引、事件事务与恢复；不反向依赖 terminal。
- 在 `qingluan-core::terminal` 放 terminal/storage 共用的领域类型与纯规则，不依赖 gRPC、SQLx 或 PTY。
- `qingluan-protocol` 承载生成的 Protobuf/RPC 类型，暂时保留原有 HTTP DTO；领域类型不直接采用生成类型。
- `qingluan daemon start` 组装模块、启动服务、处理 RPC 与领域类型转换，不维护第二套终端状态机。
- `qingluan-config` 加载和校验 socket、容量、租期等配置；`qingluan-cli` 提供人类管理与只读观察入口。
- 新增 `packages/qingluan-client`：TS 生成代码、异步封装、租约、重连和错误解码；现有 `packages/qingluan-pi` 接入审批、工具与通知。
- 顶层 `proto/` 是协议唯一定义来源，Rust/TS 从同一来源生成。
- 依赖方向为 daemon → terminal → storage → core，terminal 也直接使用 core；daemon 另依赖 protocol/config。
- terminal 统一管理状态机，storage 管理持久化事务。现有 sandbox 暂不改造，不提前抽象远端统一运行时。

## 服务、session 与控制权

- qingluan 常驻，统一管理多个 session；替代此前“每 session 一个 server”的设想。
- 由用户服务管理进程；client 只连接，服务不可用时明确报错，不自动拉起。
- 只接受本机、当前 OS 用户的客户端，通过 Unix socket 通信，不开放网络端口。
- 每个 session 可有多个终端；不同 session 不共享终端。
- 核心不依赖 pi 的 session 类型，由 adapter 映射宿主标识。
- 每个 session 同时只有一个控制客户端，可有多个只读观察端。
- 第二个控制客户端连接时拒绝，不自动抢占。
- 正常退出、reload 或切换 session 时主动释放控制权；意外断线停止发送修改操作，租约到期后释放，不以底层 gRPC 连接断开立即释放。
- 重连后必须先成功确认／续租控制权才能恢复修改；旧租约已失效则重新申请，已有其他控制端时拒绝，不抢占。
- 控制权按租约代际隔离；新控制端接管后，旧令牌不得继续提交新的写入片段。进行中的 Send 在失效后停止剩余写入，已写入字节不回滚。
- Start、Resize、Stop、确认与清理各自有明确的授权／副作用提交点，与控制权切换有序协调；已提交的停止流程不因发起者失联或租约失效撤销。
- pi 退出、reload、切换 session 只断开 adapter 的连接与订阅，不结束服务或终端。
- 同一 session 重连可找回仍运行的终端与未处理退出事件。
- 无客户端连接、长时间运行或无输出均不自动停止任务。
- 停止资源与删除历史记录分开；普通清理不能顺带终止运行中任务。

## 启动、输入与取消

- 使用显式 `program + args + cwd`，不隐式套 shell。
- 管道或重定向显式通过 shell 执行；持续交互显式启动 shell。
- 每次 start 由 adapter 传递当前 agent 进程的完整环境快照，允许本次显式覆盖。
- 不混入 qingluan 服务环境，避免 PATH、代理、SSH agent 等出现隐性差异。
- 环境变量值仅用于启动，不写入持久化日志、查询结果或通知。
- 已启动终端不随之后的环境变化而变化。
- 继承的是 agent 进程实际拥有的环境，不自动获得尚未加载的 direnv/devenv 环境。
- start/send 默认快速返回，不等待长任务完成。
- 后台指终端继续运行、agent 不必等待，不是自动给命令加 `&`。
- send 成功仅表示输入已写入，不代表命令成功。
- 发送文字默认不加回车，可显式指定提交；文字、回车、Ctrl-C 与 stop 分开表达。
- 允许多行输入，审批必须看到完整内容。
- 输入提交有界（已验证并确认为初始值，报告 §5）：分块 4 KiB；单条 Send ≤ 256 KiB，越界类型化拒绝；有界队列 2 条 + 1 条 in-flight，accepted payload backing ≤ 768 KiB；写入期限 10 s。阻塞写入可被 Stop 毫秒级中止并精确报告已写入字节（实测中止延迟 0 ms）。
- 不盲目重试 start/send 等有副作用的请求；无法确认是否执行时返回“结果未知”。查询可重试。
- 取消审批意味着不发送；操作发送后取消等待不意味着撤销。
- 已写入的输入不能可靠撤回；需要终止时显式 stop。

## 进程与服务生命周期

- 只按根进程退出产生完成通知，不猜测 shell/REPL 中每条命令是否完成。
- ProcessExited 表示根进程已退出，立即记录并通知；OutputClosed 表示输出读取已结束，不再追加。两者分开，根进程退出不保证 PTY 已 EOF。Linux 上最后一个 slave 关闭后 master read 返回 EIO 而非 EOF，实现映射为正常 OutputClosed（已验证）。
- 根进程退出后继续读取剩余输出；子进程可能仍持有终端。观察端可显示“根进程已退出，输出尚未关闭”。
- 根进程若为 SSH，退出事件意味着 SSH 退出，不代表远端每条命令的状态。
- 每个终端使用独立 cgroup v2；生产 user service 必须配置 `Delegate=yes`，缺失 delegation 或 `cgroup.kill` 时硬失败，不降级到 `/proc` 快照（部署前置条件；真实单元文件未验证，见报告 §7）。
- stop 清理终端 cgroup：先经 pidfd 向当前成员发 SIGTERM，宽限 600 ms；随后 `cgroup.kill`，最长等 3 s 至 `cgroup.events populated=0`。普通 fork、新进程组与 `setsid` 后代只要仍在终端 cgroup 内均被覆盖（已验证）。
- Stop 在内部 detached 执行且幂等：首个调用者取消不撤销，重复调用共享同一结果；输出关闭最长等 1 s，超时提交唯一 OutputClosed(Forced)（已验证）。
- 不保证回收主动迁出终端 cgroup 的进程；不保证停止 SSH 远端任务。两者是有意的非保证，不是缺陷。
- 服务正常关闭或升级重启时，停止管理的本地终端并保存状态。
- 服务重启保留记录，不恢复旧进程、连接或 shell 环境。
- 异常退出后无法确认的运行状态标记为“中断／结果未知”，不伪造正常退出码。
- SSH 复用用户已有密钥、ssh-agent 和 SSH 配置。

## 输出、查询与观察

- 保留原始输出用于留档，规范化文本用于 read/tail/grep 与只读观察。
- 查询由核心执行，不向被占用的 shell 注入查询命令。
- 每个终端有独立稳定行号，从 1 开始；轮转后不重用行号。
- 查询期间固定读取范围；显式传入读取游标，不使用共享隐式已读位置。
- 同时限制返回行数与字节数，报告截断、后续位置和已清理历史。
- 长行被字节上限截断后可以继续读取，不能只凭行号丢失剩余内容。
- 未完成行单独返回，换行后分配稳定行号；正常输出 EOF 时，最后未换行的内容也固定为历史行。
- 故障或主动关闭读取时明确标示输出可能不完整，不能冒充正常 EOF。
- 未完成行使用单独的版本／位置标识；覆写或清理导致旧位置失效时明确报错，不悄悄跳过。
- 未完成行的存储受日志容量约束，单次读取受字节上限约束，不能无限占用内存。
- 规范化支持颜色过滤、常见回车覆写和退格。
- 后续光标移动不改写已编号历史；规范化日志不是屏幕快照。
- grep 首版支持字面量搜索、大小写选项及上下文行，不支持正则。
- 观察 CLI 在独立终端运行，一次观察一个终端，先显示近期输出再跟随。
- 观察端显示规范化日志，实时更新未完成行；超长未完成行只显示有限尾部并标示省略。
- 不直接回放任意原始控制序列；不保证完整颜色或屏幕布局。
- 观察端不能输入或接管；关闭观察窗口不影响任务。
- 默认终端尺寸为 `120×30`，创建时可设置，只有控制端可调整。
- 观察窗口自行裁切或滚动，不改变目标终端尺寸。

工具名称仍是草案：`terminal_start / terminal_send / terminal_list / terminal_stop / terminal_read / terminal_tail / terminal_grep`。控制输入、尺寸调整及清理如何表达在协议中，留待选型与接口设计。

## 默认限制与留存

| 项目 | 已确认的初始值 |
| --- | --- |
| 查询默认返回上限 | 200 行 / 32 KiB，两者同时生效 |
| 查询硬上限 | 1000 行 / 256 KiB，两者同时生效 |
| 每终端日志预算 | 64 MiB，原始输出与规范化文本合计 |
| 全局日志预算 | 2 GiB |
| 每 session 活动终端数 | 8 |
| 全局活动终端数 | 32 |

- 日志预算和运行数量可配置；数量限制不是 CPU/内存沙箱。
- 达到活动终端数量上限时拒绝新建，不自动杀旧终端。Start 原子预留 session/global 两级名额，启动失败需回收资源后释放。
- 内部配额状态为 Reserved → Active → Cleaning → Released；启动失败可由 Reserved 进入 Cleaning。只有 Released 不占名额，每个名额只释放一次。
- 根进程仍运行或输出仍打开必然占位；即使进程／输出已结束，也要等管理资源回收完成才释放，不能仅凭根退出释放配额。
- 日志达到预算时轮转最旧记录，明确标示缺失范围，优先保持任务运行。
- 全局预算不足时优先清理已退出终端的旧日志，再清理运行中终端的旧日志。
- 终端退出不立即删除记录。
- 不自动删除 session 身份或终端退出状态；提供显式清理入口。
- 存储初始值已确认（设计值，未在边界实测，见[验证报告](../research/terminal-technical-validation.md) §6）：segment 4 MiB 起步；持久化批处理 64 KiB 或 50 ms 先到为准；每个 terminal 最多保留 64 条 segment 元数据；合并 gap 记录上限 1024。探针的 256 KiB 段与 4096 B 场景阈值属探针机制，不是生产值。不承诺所有磁盘占用都已被上述日志预算覆盖。

## 磁盘故障

- 磁盘满、只读或 I/O 错误时，现有任务继续运行。
- 持续排空 PTY，避免因持久化阻塞而卡住程序。
- 使用有上限的内存缓冲；超限丢弃并报告记录缺失。
- 服务标记为降级并拒绝新建终端。
- 故障期间不保证日志和退出事件持久化，不能假报落盘成功。

## 权限、安全与通知边界

- 首版要求通过 pi 工具发起的操作先经过宿主权限检查。
- 不声称可阻止同一 OS 用户下的任意代码直接调用 qingluan 或自行执行命令；这不是 OS 安全隔离。
- TS client 不是安全边界；不能因插件有审批框就声称所有 server 入口都受审批保护。
- 新工具规则需要显式核实，不静默修改用户权限配置。
- start 的命令审查与 send 的状态相关、不透明输入审查分开，不能把 send 伪装成独立 bash 命令。
- 不单独持久化原始输入，只保留必要操作元数据。
- 终端回显可能把输入和环境信息带入输出；日志可能含秘密，首版不承诺自动脱敏。
- 正常情况下根进程退出只通知一次；核心保存退出事件，adapter 按事件 ID 恢复、确认与去重。
- 优先避免漏报；崩溃发生在发送与确认之间时允许重复，不承诺 exactly-once。
- 重连时汇总积压退出事件，避免逐事件唤醒 agent。
- session 切换或 reload 后，旧订阅不得将通知投递到新 session。

现有 dsh 权限研究保留在 `../pi-extensions/docs/research/deepseek-harness-permissions.md`（相对本仓库根目录），不在此复制。研究结论基于静态核验，不代表本项目运行验证。

## 验收顺序与停止条件

1. 本地创建 PTY、发送输入、有限查询、只读观察、停止与显式清理。
2. 多 session 隔离、单控制端互斥、客户端断开任务继续、重连及旧控制端失效。
3. 日志轮转、长行续读、退出事件恢复、服务重启和异常处理。
4. pi 工具、审批拦截、取消与参数一致性、完成通知。
5. 使用已有 SSH 配置验证普通 SSH 场景。

先使用本地轻量命令，不使用真实 GPU 训练任务试错。完成上述闭环即停止，不扩展首版非目标。

## 已确认的技术选型

- 使用 Protocol Buffers `proto3` 作为跨语言协议定义和消息编码。
- 使用 gRPC over Unix socket，不自行设计消息分帧和 RPC 协议，不开放网络端口。
- 普通操作使用单次 RPC，输出及退出事件使用流式订阅。
- 首版 RPC 集中于一个 `TerminalService`，暂不抽象通用 Session 服务。
- 控制权采用显式令牌与租约，通过获取、续租、释放管理；不把底层 gRPC 连接身份直接等同于控制客户端。租约过期或释放后旧令牌失效。
- 控制权、事件持久化、恢复去重和断线后的结果未知仍由应用层实现，不能视为 gRPC 自动提供的保证。
- Rust 使用 `tonic` 实现 gRPC、`prost` 处理 Protobuf；TS 使用 `@grpc/grpc-js`，由 `ts-proto` 生成类型、编解码及 RPC stub。
- 构建时静态生成代码，不在运行时加载 `.proto`；手写 TS client 封装异步调用和 session 管理。
- Rust 与 TS 生成产物均不提交仓库；构建后提供生成类型及编辑器支持。此前建议提交 TS 生成文件未被采纳。
- 生成必须接入 build/typecheck 的前置流程，不依赖开发者记住额外手动步骤；具体任务命名和构建集成尚未实现。
- 生成工具采用 protoc，复用 just 统一入口；Rust 使用 tonic/prost 构建工具，TS 使用 ts-proto，首版不引入 Buf。
- 外部协议定义（如 google.rpc.Status）固定版本随仓库保存，记录来源及许可；构建不临时联网下载协议。生成工具通过现有 Nix/devenv 声明，具体版本与文件尚未落地。
- TS client 首版面向 Node.js，不承诺浏览器支持。
- TS 的 64 位整数使用 `bigint`；进入工具 JSON 结果时转换为十进制字符串，避免精度损失。
- 需要区分未传与零值的字段使用 `optional`；删除字段后保留其编号，避免复用。
- PTY 采用 `pty-process` 0.5.3（`async`）负责 open/spawn/read/resize；写端使用 master fd duplicate 加自管 `AsyncFd` 非阻塞写入，以固定 Stop 与租约代际的提交顺序——这是 Gate B 确认的采用条件，不是可选优化。cgroup 与信号操作使用 `nix` 与 pidfd。
- PTY 生命周期、Stop 屏障、配额回收与 registry 恢复已通过 Gate B 运行验证（25 场景 + 6 单测，冷/热两轮，原始日志 `/tmp/pty-verify-cold.log` 与 `/tmp/pty-verify-warm.log`；证据见报告 §5）。OS session 与 qingluan session 是不同概念。
- 交互 shell 的前台任务可能属于不同进程组；不能把终止根进程组视为整个终端的完整清理，改按 cgroup 成员清理（已验证）。主动迁出 cgroup 的进程仍不保证回收。
- 存储采用分段日志文件 + SQLite 元数据：文件保存原始输出、规范化文本与行定位信息；SQLite 保存 session/terminal 状态、退出事件及消费确认、日志段目录与范围索引。
- 文件与数据库不构成同一原子事务；提交顺序已验证：append 完整帧 → `sync_data` → 短 SQLite 事务 → 提交后才发布，首次建段强制 header sync 与父目录 fsync（crash matrix + 断电变体，报告 §6）。恢复已验证：坏／半／未索引尾部一律截断回 committed 边界并隔离、永不采纳；索引指向缺失／截短／损坏段时显式 gap + 降级；行号水位不回退、编号不复用；恢复幂等；正常重启与轮转保持 epoch，破坏性重建才换代并拒绝旧游标。原始与规范化日志共同计入预算，首版不引入全文搜索引擎。
- SQLite 使用 SQLx 接入，复用其异步接口与后台线程，避免自行维护同步 SQLite 到 Tokio 的桥接。
- 仅启用 SQLite，不引入 ORM 或跨数据库抽象；使用版本化 SQL 迁移，首版使用运行时查询，不引入编译时查询宏及离线元数据。
- 数据库事务保持短小，不包含日志扫描或等待客户端。
- 输出解析使用 Rust `vte`，在其控制序列解析之上实现有限行式规范化，不使用屏幕快照作为稳定历史行的来源。
- 规范化处理换行、回车覆写、退格、制表符、常见行内移动与清除；丢弃样式及 OSC 等控制指令，不执行剪贴板或标题修改。
- 屏幕宽度导致的自动折行不生成新历史行；跨行光标操作不改写已编号历史，不承诺全屏程序的可读性。
- `vte` 不负责行编辑语义；实现需要验证中文宽字符、组合字符、超长行及跨数据块输入，目前未运行验证。
- 依赖版本已锁定（tonic/prost 0.14.x、grpc-js 1.14.5、ts-proto 2.12.4、pty-process 0.5.3、sqlx 0.9.0、vte 0.15.0，精确清单见报告 §2）；UDS 互操作、bigint 精度、presence、未知字段／枚举容忍、流取消与 richer error 解码降级已通过 Gate A 运行验证。Node.js 实测 24.19.0 与 22.23.2；最低候选 22.12.0 未单独执行。

## 协议 v1：已确认的执行语义

### Session 身份与控制租约

- SessionRef 由 source（例如 pi）与 external_id（宿主 session ID）共同标识；范围为当前 OS 用户。
- cwd、workspace 和连接 ID 不参与 session 身份；不同 source 下相同 external_id 不混用。
- 首次获取控制权时创建 session 记录，不另设通用 CreateSession 流程；查询不存在的 session 明确报不存在。
- AcquireControl 返回令牌、有效期及 session 事件状态快照（已确认、最后已提交、已清理前缀三个水位），使新控制端可以接续消费。
- 正常退出、reload、切换 session 主动 ReleaseControl；意外断线依靠租约到期释放，不等同于底层连接关闭。
- 重连必须先成功确认／续租才能恢复修改。失效后重新申请；已有其他控制端则拒绝，不抢占。
- 初始租期 30 秒，client 每 10 秒续租；server 使用单调时钟判定，客户端倒计时仅作参考。
- daemon 重启使所有旧控制令牌失效。崩溃且未主动释放的客户端可能占用控制权至剩余租期结束。
- Start/Send/Stop/Resize、显式删除记录及事件确认需要有效控制权；List/Read/Tail/Grep 与只读订阅不需要控制令牌。
- 控制令牌仅用于所属 session；操作 terminal 时验证其归属。
- 令牌只保存在 client 内存，不写入日志、工具结果或模型上下文；观察端不能确认控制端尚未处理的退出事件。
- 上述规则是应用层控制权，不构成同用户代码之间的安全隔离。

### Start

- 请求包含 session 引用、控制令牌、program、args、绝对 cwd、完整环境快照与终端尺寸。
- 环境快照必须显式提供；空环境合法，未提供则拒绝，不回退到 daemon 环境。
- cwd 不存在或程序启动失败时明确报错，不替换目录、程序或 shell。
- 成功表示 PTY 已创建、根进程已启动，返回 terminal_id，不是仅接受排队。
- 根进程可能立即退出，成功响应不保证客户端收到时仍在运行。

### Send

- 请求包含 terminal_id、控制令牌及最终输入 data（bytes），协议不再包含 text + submit 两套语义。
- TS client 提供固定转换：文字转 UTF-8，显式提交追加回车，Ctrl-C 等转换为对应控制字节。
- adapter 确保审批内容与最终发送字节一致；控制字节受终端模式影响，不等价于直接向进程发送信号。
- 响应报告实际写入字节数；完整成功仅表示输入已写入 PTY master，不表示程序已读取或命令成功。
- 部分写入或连接中断后不得自动重发整段输入；已知写入量通过 PARTIAL_WRITE 结构化错误详情报告，最终字段布局待冻结。

### Stop

- 成功表示已进入停止流程，返回当前状态，不等待温和退出期限结束。
- 根进程结束由退出事件报告；重复 stop 不重复启动停止流程。
- 根进程已退出但输出仍打开时，Stop 仍尽力清理终端 cgroup 并关闭 PTY，输出标记为主动关闭／可能不完整；保留已知根进程退出结果，不重复通知。主动迁出 cgroup 的进程与 SSH 远端任务不在此清理边界内（有意非保证，见“进程与服务生命周期”）。
- 仅当进程与输出均已结束时，Stop 直接返回已有状态；不存在则报不存在，不伪装成已停止。

### 修改顺序

- 同一终端的普通 Send/Resize 有序执行，不交错两个 Send；client 需要确定顺序时等待前一次响应，并发请求不保证按客户端发起时间执行。
- Stop 是可中止阻塞写入的屏障，不是普通 FIFO 项；停止意图提交后拒绝新 Send、取消未开始输入、中止进行中 Send 的剩余片段，并在有界时间内进入停止流程。
- 服务端输入消息与写入分块有界，写入等待有服务端期限且响应 Stop／租约失效／服务关闭；每片实际写入与租约切换有确定顺序，不能只在入队时校验。
- 中止后通过 PARTIAL_WRITE 报告已知写入量；无法送达响应则 client 仍报结果未知。已写入字节不可撤回，已提交 Stop 继续完成。
- 查询与观察不进入输入队列，避免慢写入阻塞读取。

### 状态与清理

- 终端快照分别报告进程状态（运行中／已退出／因服务异常而结果未知）、输出状态（打开／正常结束／异常或主动关闭）、是否正在停止，以及已知退出码或终止信号。
- 不使用 -1 混代全部异常；允许表达“根进程已退出，输出仍打开”。最终状态枚举及启动中状态的表达尚待消息设计细化。
- 根进程仍运行或输出仍打开均占用活动终端配额；预留与尚未清理完成的管理资源同样占位，只有完整回收后释放。
- 清理日志与删除终端记录分开：日志清理可对运行中终端执行，不杀进程、不删除退出事件、不重置行号。
- 只有资源已回收、生命周期事件提交完结且没有未确认事件时，才允许删除终端记录。
- 记录删除不级联删除未 Prune 的已确认事件；事件自身包含解释所需信息，重放不依赖终端记录仍存在。
- 首版不提供强制删除并自动杀进程的组合操作；需要先 Stop，再清理。

## 协议 v1：已确认的查询语义

### Read

- 首次读取确定本轮历史上界，后续分页沿用，不随新增输出扩展。
- Read 游标绑定 session/terminal_id、持久化日志代际、下一历史行及行内 byte_offset、固定 end_line，支持长行续读；最终字段编号尚未冻结。
- 普通重启与轮转不改变日志代际；破坏性重建导致位置失效时才换代并拒绝旧游标。最早可用位置包含行内偏移，能表达超长行前缀丢失。
- 响应包含内容、后续游标、截断原因与当前最早可用位置；UTF-8 文本尽量在完整字符边界截断。
- 历史被轮转时明确报游标失效，提供最早可用位置，不自动跳过缺失内容。
- 固定读取范围不意味着锁住历史阻止轮转。

### Tail

- 返回行数与字节预算内的最近历史内容、单独的未完成行快照，以及可直接传入 ObserveTerminal 的类型化衔接位置。
- 历史、尾部与衔接位置来自一致切面；观察游标包含日志身份、下一历史位置、已见尾部版本／位置和状态版本。
- 尾部固定成历史行时保留尾部身份／最终版本到行号的映射直到历史清理；旧版本因覆写不可恢复时明确失效，不悄悄拼接新尾部。
- 若预算只能容纳长行尾部，明确标示省略前缀，并提供行定位供 Read 补读。
- 不维护隐式共享已读状态。

### Grep

- 首版仅搜索已固定历史行，不搜索变化中的未完成行。
- 返回匹配行号、匹配位置及有限上下文。
- 除返回量上限外，另设单次扫描预算；未扫完返回扫描续点。
- 本批无匹配不等于整个固定范围无匹配。
- 分页期间固定搜索词、选项与历史范围。

### 输出结束

- ProcessExited 与 OutputClosed 独立，不因根进程退出丢弃剩余输出。
- 正常 EOF 时将最后未换行的尾部固定成历史行。
- 故障或主动关闭读取必须标示可能不完整；状态与结束原因的最终协议表达尚待细化。

## 协议 v1：已确认的事件与错误语义

### 持久化事件

- 每个 session 一条持久化事件序列，包含 session、event_seq、terminal_id、事件类型与内容。
- event_seq 在 SQLite 事务中分配，与终端退出状态同事务提交；只有提交成功后才向持久化流公开。
- 已公开 event_seq 在 session 内单调递增，重启后不重用；未提交且未公开的候选编号不构成已发生事件。
- 磁盘提交失败时不向 WatchSessionEvents 发送未落盘序号，流以明确降级错误终止／拒绝订阅；非持久化状态观察可报告降级，不提供虚假的重放／确认保证。
- 恢复后可补写的内存事件提交成功后再公开；事实已丢失则明确报告可能不完整／中断，不伪造退出结果。
- 输出正文不进入生命周期事件序列；OutputClosed 更新状态，不额外触发任务完成通知。

### 消费确认

- 一个 session 共用一个 agent 消费进度；新控制客户端接续已保存的确认位置。
- 订阅显式指定 after_event_seq，不使用连接内隐式游标。
- AckSessionEvents(up_to_seq) 累计确认此前事件均已处理；重复确认无害，确认位置不回退且不得超过已有事件上界。
- 只有有效控制端能确认，观察端订阅不推进 agent 消费位置。
- 确认仅代表 adapter 已处理，不代表人类或模型已读；通知与确认不构成原子事务，崩溃边界仍允许重复。

### 事件留存

- 首版事件不自动过期，通过显式清理删除，不随输出日志轮转。
- PruneSessionEvents 只清理已确认事件的连续前缀；删除与 pruned_through_seq 更新同事务完成，不降低 last_committed_seq 或 acked_through_seq。
- 清理导致订阅位置无法恢复时，明确报告事件历史已清理及可用范围，不静默跳到最新位置。

### 错误返回

- 使用 gRPC status 表示错误大类，结构化详情提供稳定原因码与恢复信息，不套用旧 HTTP ApiResponse 成功／失败包装。
- 原因码包括 CONTROL_BUSY（可参考剩余租期，不暴露令牌）、CONTROL_EXPIRED、CURSOR_EXPIRED（最早可用位置）、TERMINAL_NOT_WRITABLE（当前状态）、PARTIAL_WRITE（已知写入字节数）；最终枚举及字段编号尚未冻结。
- 服务端知道部分写入量时报告它；连接断开且未收到详情时 client 报结果未知，不把缺失写入量当成零。
- 错误载体采用 grpc-status-details-bin 中的 google.rpc.Status，通过 Any 携带本服务 ErrorDetail（reason + typed oneof）；不是裸 ErrorDetail 字节或 JSON。
- TS client 显式解码并校验 binary metadata；未知／损坏／内外状态冲突的详情降级为通用失败，不自动重试。未知写入量、未知剩余租期及缺失恢复位置不得用零值替代。
- 载体已完成 tonic/grpc-js 互操作验证（含畸形、未知与冲突详情的降级路径，报告 §4）；字段编号和 helper 依赖仍未冻结。

## 协议 v1：已确认的版本与恢复规则

- GetServerInfo 返回 daemon 版本、支持的协议主版本和已实现的可选能力。
- 主版本不兼容时 client 拒绝执行；同一 v1 优先增量兼容，不以软件版本号代替协议版本。
- 观察端积压超过有界缓冲上限时，server 终止该观察流并返回明确原因；client 携最后成功接收的位置重订阅。
- 历史已轮转时明确报告缺口，由调用方决定从哪里继续；不无限排队、不静默跳到最新，也不因观察端慢而停止排空 PTY。
- 退出事件使用独立持久化序列恢复，不与输出观察的缓冲策略混用。
- terminal_id 不复用；删除终端记录不重置 session 的事件序号或确认进度。
- 已确认事件可显式清理，但保留必要的序号水位和清理范围。
- 首版不提供删除并重建整个 session 身份的 RPC，避免旧游标误指向新历史。
